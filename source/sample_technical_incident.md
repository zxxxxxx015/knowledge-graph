# APC 控制器異常延遲測試案例

## 場景背景

此測試文件描述一個 APC 控制器在高負載狀態下產生控制延遲的案例。

APC 控制器每 100 ms 接收一次感測器資料，並依照 PID 控制邏輯更新閥門開度。

當資料採集服務延遲時，控制器會使用上一筆有效感測值維持閉迴路控制。

## 觀測指標

- CPU 使用率高於 90% 持續 30 秒時，控制迴圈延遲會明顯增加。
- 感測器資料延遲超過 250 ms 時，控制器會標記資料品質為 stale。
- 閥門開度變化率超過每秒 12% 時，系統會提高採樣頻率。
- 控制迴圈延遲的正常範圍應低於 120 ms。

## 異常條件

- 當 CPU 使用率高於 90% 且資料佇列長度超過 500 筆時，控制器可能無法即時處理新資料。
- 當感測器資料連續三次逾時時，APC 控制器會進入降級模式。
- 當網路封包遺失率高於 5% 時，資料採集服務會重送遺失封包。

## 作用機制

資料採集服務會先將感測器資料寫入佇列，再由控制器讀取最新資料進行控制計算。

如果資料佇列累積過多，控制器讀取到的感測值會落後於現場設備狀態。

PID 控制邏輯會根據目標值與量測值的誤差計算閥門開度。

降級模式會限制閥門開度變化率，避免延遲資料造成過度控制。

## 影響結果

- 控制迴圈延遲增加會造成閥門開度更新變慢。
- 閥門開度更新變慢會導致壓力調節時間拉長。
- 壓力調節時間拉長可能造成產線流量波動。
- 資料品質為 stale 時，監控畫面應顯示黃色警示。

## 處置方式

- 當控制迴圈延遲超過 120 ms 時，系統應記錄 performance warning。
- 當降級模式啟動時，操作員應檢查 CPU 使用率、資料佇列長度與封包遺失率。
- 若資料佇列長度持續超過 500 筆，應重新啟動資料採集服務。
- 若 CPU 使用率持續高於 90%，應降低非關鍵診斷任務的執行頻率。

## 定義

stale 資料是指感測器資料的時間戳落後目前控制週期超過允許門檻。

控制迴圈延遲是指感測器資料進入控制器到閥門命令輸出之間的時間差。

降級模式是 APC 控制器在資料品質不足或處理延遲過高時採用的保護狀態。

## 多句段落測試

APC 控制器延遲升高時，監控系統會記錄異常事件。CPU 使用率持續偏高時，資料採集服務的處理延遲可能增加。操作員確認降級模式啟動後，應檢查資料佇列長度。

## 測試表格

| 測試項目 | 觸發條件 | 預期結果 |
| --- | --- | --- |
| 高 CPU 負載 | CPU 使用率高於 90% 持續 30 秒 | 控制迴圈延遲增加並記錄 performance warning |
| 資料逾時 | 感測器資料延遲超過 250 ms | 資料品質標記為 stale |
| 佇列壅塞 | 資料佇列長度超過 500 筆 | 控制器可能讀取到過期感測值 |
