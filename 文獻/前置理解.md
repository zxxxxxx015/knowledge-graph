# 前置理解

## 1. 核心目標

將資料來源轉換成可辨識、可連接、可追溯的知識圖譜資料。轉換過程不得破壞原始資料內容，且每個階段都必須保留前一階段的痕跡。

## 2. 基本概念

| 概念 | 定義 |
| --- | --- |
| 資料來源 | 原始文件或其他輸入內容，不直接修改。 |
| 知識條文 | 從資料來源逐句拆出的完整內容。拆分只做切割，不自行刪減或改寫知識。 |
| 知識項 | 從知識條文中辨識出的知識單位。一條知識條文可以包含多個知識項。 |
| 知識包 | 知識項在因果鏈中所屬的功能維度。 |

## 3. 六大知識包

正式名稱與順序如下：

**觀察 → 理解 → 根因 → 推論 → 行動 → 策略**

| 順序 | 知識包 | 說明 |
| --- | --- | --- |
| 1 | 觀察 | 實際觀測到的狀態、數值、事件或條件。 |
| 2 | 理解 | 對觀察內容的意義或狀態解讀。 |
| 3 | 根因 | 導致目前狀態或事件的原因。 |
| 4 | 推論 | 由目前內容推導出的影響、結果或可能發展。 |
| 5 | 行動 | 具體需要執行的處置。 |
| 6 | 策略 | 為達成目的而採取的整體方向。 |

> 來源：第二個版本《知識圖譜專案的詞彙定義》之「知識包」段落；本版本將「觀測」改為「觀察」。

## 4. 建置原則

- 不直接修改資料來源。
- 將資料來源切割成知識條文時照搬原文，不自行刪減知識。
- 每個步驟都保留前一步的輸出與來源對應，確保內容可以回溯。
- 所有輸出檔均使用 JSON，內容保持乾淨、整潔，只保留必要欄位。
- 優先沿用既有 ID；只有在沒有可沿用的對象時才建立新 ID。
- 各階段輸出具有連貫性，不任意丟棄前一階段的內容。
- 無知識價值的內容可以在知識項提取階段標記為過濾，不得影響可追溯性。
- LLM 補充或推論的內容，必須與原始內容分開標記，並保留依據。

## 5. 建置步驟

| 步驟 | 名稱 | 輸出 |
| --- | --- | --- |
| 第 0 步 | 資料前處理 | 將資料來源內文中的代名詞或指示性簡稱，例如「此」、「其」、「該」等，替換成實際指涉的名詞。保留原文與替換後內容的對應。 |
| 第 1 步 | 句子拆分 | 將前處理後的內容拆成一條一條的知識條文。保留原始文件、位置、原文與拆分結果的對應。 |
| 第 2 步 | 知識項提取與知識價值過濾 | 從每一條知識條文提取一個或多個知識項。例如「APC 控制器每 100 ms 接收一次感測器資料，並依照 PID 控制邏輯更新閥門開度。」可提取 APC 控制器、PID 控制邏輯、閥門開度等知識項。對沒有知識價值的條文進行標記或過濾，保留處理痕跡。 |
| 第 3 步 | 知識包分類 | 根據知識項與知識條文的本質屬性，分類至觀察、理解、根因、推論、行動、策略六大知識包。保留原知識條文與知識項的關聯。 |
| 第 4 步 | 因果鏈建立 | 依照知識條文中的條件、狀態、原因與結果建立因果鏈。例如「CPU 使用率高於 90% 持續 30 秒時，控制迴圈延遲會明顯增加」可分為：觀察：CPU 使用率高於 90% 持續 30 秒；推論：控制迴圈延遲會明顯增加。沿用既有知識項 ID。 |
| 第 5 步 | 來源定義查找 | 在資料來源中尋找各知識項的定義，並將定義連結至對應知識項。 |
| 第 6 步 | 缺失定義補齊 | 使用 LLM 補齊資料來源未提供的知識項定義，標記為 LLM 補充，並保留補充依據與對應知識項 ID。 |
| 第 7 步 | 因果鏈補齊 | 使用 LLM 補齊因果鏈中缺少但可由既有內容支持的環節，標記為 LLM 補充或推論，並保留對應依據與既有節點 ID。 |
| 第 8 步 | 內容整合 | 整合所有知識條文、知識項、知識包、因果鏈、定義、來源與處理痕跡，輸出可供後續建圖使用的 JSON。 |

## 6. 溯源要求

每個輸出內容至少保留以下關聯：

- 原始資料來源識別。
- 原始文件中的位置，例如頁碼、行號或字元範圍。
- 前一步輸出的 ID。
- 目前輸出的 ID，以及沿用或新建的狀態。
- 若內容由 LLM 補充或推論，記錄其來源依據與生成標記。

## 7. 因果鏈示例

```text
觀察：CPU 使用率高於 90% 持續 30 秒
  ↓
推論：控制迴圈延遲會明顯增加
```
